Distributed Bird Monitoring

In development

Offline field nodes, lossless sync, and a native iOS companion.

I'm building a network of bird-monitoring nodes for places where connectivity cannot be assumed. BirdNET inference runs at the edge, while a Swift central service and iOS companion handle the fleet when a path home is available.

One protocol, three Swift products

I keep the detection envelope, sync session, management API, and compact radio frames in a dependency-free Swift package. The field node, central service, and iOS companion all compile against those same definitions instead of maintaining parallel versions.

Field nodes that work offline

The headless node captures audio, runs BirdNET through TFLite, records detections in SQLite, and queues them in a durable outbox. Clips and sync checkpoints stay local until the node can reach the central service again.

More than one way home

Nodes initiate resumable sync sessions over IP when it is available. The transport boundary can also select compact radio frames through a Reticulum sidecar; contract tests enforce the byte budget before the data ever reaches real radio hardware.

Running on real hardware

The Swift node builds and runs on a Raspberry Pi 5, the central service and MQTT broker run on an Arduino Uno Q, and a Pi Zero 2 W captures from a Pirate Audio dual-mic board while driving its small display.

The iOS companion already consumes fleet, detection, clip, and live-update contracts. Its interface is still under development, so I'm treating this as a working system rather than presenting it as a finished app.
