I built Splats to inspect Gaussian-splat scenes from my own captures. It opens local files and renders them with Metal on Mac, iPad, and iPhone.

Gaussian splatting represents a scene with millions of small, view-dependent ellipsoids instead of a triangle mesh. I started building Splats because I needed a better way to inspect scenes I had trained from my own footage, especially when I was chasing camera or sorting problems.

Local-first scene viewer

I wanted Splats to behave like an ordinary Mac or iOS app, not a graphics demo. It opens scenes from local files, keeps a list of recent scenes, and works offline once a file is on the device.

I keep the controls I use most in native panels beside the scene: orbit and fly navigation, zoom-through, gesture help, frame-rate controls, stable rendering, and renderer tuning.

Renderer architecture

I keep app state, interface code, file loading, and rendering in separate frameworks generated with Tuist. TCA handles the state and behavior, while SwiftUI provides a thin layer over the shared renderer on each platform.

Gaussian splats have to be sorted back to front as the camera moves. The Stable Render option waits for that sort to finish before drawing, which avoids the brief holes that can otherwise appear in a scene.

Capture-to-splat pipeline

I use my own footage as a repeatable test set. I extract frames, use DJI telemetry when it is available, reconstruct the camera poses with COLMAP, undistort the reconstruction to a pinhole camera model, and train the scene with Brush.

Brush exports PLY files for the native app. For the interactive scenes on this site, I convert the same result to SOG so it is small enough to load in the browser.

Splatpaper on Mac

On macOS, Splatpaper turns a chosen scene into a slow-moving live wallpaper. It loads the original scene file through the same path as the viewer, so wallpaper mode uses the real renderer rather than a separate video export.
