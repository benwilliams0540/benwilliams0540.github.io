Splats

A native Gaussian-splat viewer for macOS, iPadOS, and iOS — rendered in Metal.

Splats opens Gaussian-splat scene files and renders them through a Metal pipeline, with platform-tuned camera controls and a macOS menu-bar "Splatpaper" live-wallpaper mode. It's backed by a full COLMAP-to-splat training pipeline I run on Apple Silicon.

Splats is a native viewer for 3D Gaussian splatting — a scene representation where geometry is millions of view-dependent, anisotropic "splats" rather than triangles. The app opens a splat file, hands it to a Metal renderer, and keeps camera and file controls within reach on each platform: orbit, pan, scroll/pinch zoom, dolly-through movement, and automatic rotation.

I built it end to end — the SwiftUI/Metal application and the data pipeline that produces the scenes it renders. The scene you can fly around lower on this page was reconstructed from my own drone footage through that pipeline.

Architecture

The Tuist project splits into focused frameworks so state, UI, and the renderer stay independently testable. State and behavior live in TCA reducers; the SwiftUI shell is a thin, cross-platform layer over them.

  • SplatsFeature — application state and behavior (TCA + Sharing for recent models).
  • SplatsUI — the cross-platform SwiftUI shell: overlays, file browser, loading panel, camera controls.
  • SplatsViewer — bridges SwiftUI into the Metal splat renderer (MetalSplatter + SplatIO).
  • SplatpaperWallpaperFeature — the macOS wallpaper-mode state.
  • SplatsMac / SplatsiOS — thin platform entry points over the shared frameworks.

Making the first frame trustworthy

Splat scenes converge as they sort back-to-front, so a naive viewer shows transient holes while the scene settles. The camera panel exposes a "Stable render" switch: when enabled, the renderer waits briefly for sorting and schedules a few redraws after sort completion, which removes the early holes. Turning it off is useful for measuring true load and first-frame timing.

Camera gestures are translated into TCA actions rather than handled ad hoc in the view, so pointer and touch behavior stay tunable and testable across macOS, iPad, and iPhone.

Splatpaper — splats as a live wallpaper

On macOS, Splatpaper runs a chosen splat scene as a slow-rotating desktop wallpaper from a menu-bar control, with tunable rotation speed and frame pacing. It shares the same renderer and state machine as the in-app viewer rather than forking a second code path.

Performance

I benchmark active rendering cost with a local control harness, sampling CPU and memory once per second across scenarios. A visible scene with rotation off settles to about 4.7% CPU and ~286 MB; continuous rotation costs roughly one full CPU core. The captures feed a follow-up list — e.g. why the sort loop stays warm when a settled scene isn't moving.

The capture-to-splat pipeline

The scenes Splats renders come from a reproducible Apple-Silicon workflow: extract frames from DJI drone clips, parse SRT telemetry into GPS pose priors, reconstruct camera poses with COLMAP, undistort to pinhole cameras, then train with Brush (with OpenSplat and MLX as comparison trainers). Hard-won lesson: sheets and floaters are almost always a COLMAP, undistortion, or match-density problem — not bad footage — so I verify the reconstruction before spending hours on longer training runs.

  • Frame extraction + DJI SRT → GPS pose priors for flat, repetitive scenes.
  • COLMAP feature extraction, sequential matching, and pose-prior mapping (CPU-only on macOS).
  • Mandatory undistortion before trainers that assume pinhole cameras.
  • Brush / OpenSplat / MLX trainer comparisons on one shared undistorted dataset.
  • PLY → SOG conversion (a Swift script) for compact, web-deliverable scenes.
